# ICPC / CCPC 程序设计竞赛 · 考试档案

> 竞赛与考试的根本差别：**没有标准答案，只有测试点**。组卷产出的是“题面 + 约束 + 样例 + 测试点设计 + 题解”，判分按通过测试点与罚时。

## 一、事实（公开赛制）

| 项 | 内容 |
|---|---|
| 全称 | International Collegiate Programming Contest（ICPC）；中国赛区对应 CCPC |
| 队伍 | 3 人一队，共用 1 台机器 |
| 时长 | 5 小时（区域赛标准） |
| 题量 | 通常 8–13 题（区域赛多为 10–13 题） |
| 判定 | 每题若干测试点，全部通过才算 Accepted（AC） |
| 罚时 | 每题首次 AC 前，每次错误提交罚 20 分钟；未 AC 的题不计罚时 |
| 排名 | 先比题数，再比罚时；同题数同罚时按最后一次 AC 时间 |
| 环境 | 无互联网、无外部资料；可用自带模板与纸质材料（以当届规则为准） |
| 赛中信号 | 过题气球（颜色对应题号） |

## 二、题目结构 `[推定]`

无官方“结构表”，按区域赛常见配比归纳：

| 难度带 | 题量 `[推定]` | 目标 | 典型考点 |
|---|---|---|---|
| 签到 | 1–2 | 10 分钟内 AC | 模拟、简单排序、读入处理 |
| 常规 | 3–5 | 单人 30–60 分钟 | 贪心、二分、前缀和、基础 DP、并查集 |
| 中高 | 3–4 | 需两人讨论 | 图论、区间 DP、树、数论、构造 |
| 压台 | 1–2 | 往往赛末才有人过 | 高级数据结构、计算几何、复杂构造 |

## 三、高频考点

1. 模拟 / 实现（读入格式、浮点、多测）
2. 贪心与交换论证
3. 二分（答案二分、交互二分）
4. 动态规划（线性、区间、树形、状压入门）
5. 图论（最短路、生成树、拓扑、二分图匹配入门）
6. 数据结构（并查集、树状数组、线段树、单调栈/队列）
7. 数论（gcd/扩展欧几里得、筛法、同余、组合计数）
8. 字符串（哈希、KMP、Trie）
9. 构造题与交互题（ICPC 特色）

## 四、评分与判分口径

- **没有部分分**：测试点全过才 AC。因此组卷必须给“**测试点设计**”：小样例、边界、极端、随机对拍、卡常数据。
- 判分报告按**队伍维度**输出：AC 时间线、每题提交次数、罚时合计、卡住的题、可回收的罚时（首题前无效提交）。
- 教练视角要额外给：**赛中决策复盘**（开题顺序、卡题止损时间、双人并行分配）。

## 五、情报现状

- 赛制公开且稳定，可直接引用。
- 具体赛事题量与配比随赛区浮动，只能给区间，不给精确数字。
- 平台侧：2026-11 在 Agensi 检索 competitive programming，已有通用 CP 教练（如 VoidHub CP Coach），但**没有按 ICPC 罚时与测试点口径组卷 + 复盘**的技能。
