# 万能模拟考试（Universal Mock Exam）

把"备考"变成一条可复用流水线：**锁定需求 → 双源考情建模 → 命题画像 → 高拟合组卷 → 全真作答 → 判分与提分**。

## 核心契约

1. **先画像，后命题。** 没有命题画像就不出题；每道题必须能追溯到某个考点、某个维度、某个难度档。
2. **拟合四维达标。** 考点权重、题型结构、难度分布、命题风格，四项都要与目标考试对齐，而不是"看起来像"。
3. **双源情报。** 官方源（考纲、大纲、样卷、真题、考试说明）定骨架；民间源（短视频、内容平台、机构分析、考生实测）调权重、补风向。两者冲突时官方优先。
4. **透明标注。** 每套卷标注生成依据与预测性内容占比；每道题标注 `官方考纲 / 共识预测 / 拓展补充`。绝不把博主押题包装成官方结论。
5. **闭环提分。** 判分不止给分数：给采分点、给错因、给"高价值失分点"，再生成专项卷。

## 主流程

### Step 0　锁定需求（1 轮内完成）

必须确认或合理默认：考试全称与级别、考试日期（倒推可用备考天数）、目标分数/档位、可用总时长、题库来源（通用生成 / 用户资料 / 指定教材章节）、输出形态（在线作答 / 打印卷 / 文档）。

缺省值：目标分取"优秀档下限"；备考时长未知则按考试日期倒推；题型未知则按画像标准结构。所有默认值在卷首声明。

### Step 1　官方考情建模

检索并落地：官方考纲/考试大纲、样卷/样题、历年真题（题目结构而非原文）、评分标准、级别适配说明、考试形式与时长。

按 `references/exam-intel.md` 的检索模板执行，产出**官方骨架表**：题型清单、各题型题量与分值、模块划分、时长、及格与档位线、语言与作答方式。

### Step 2　民间情报采集与综合

按 `references/exam-intel.md` 的平台清单与可信度分层采集，只提取可结构化、可影响命题的信息：高频考点、新增/删减考点、题型变化、难度走势、命题话术、阅卷与采分变化、反押题预警。

产出《考情趋势补充报告》：共识考点 Top N、结构性变化、风格差异、失分重灾区。**情报稀薄时降级**为"官方 + 考生实测反馈"，并在报告中写明"民间情报不足，未上调任何预测权重"。

### Step 3　命题画像（四表）

写入 `exam_spec.json` 的 `profile` 字段，作为组卷唯一依据：

- **考点权重表**：模块 / 考点 / 分值占比 / 考查频次 / 常考题型
- **题型矩阵**：题型 / 题量 / 单题分 / 分值合计 / 建议用时
- **难度结构**：易:中:难比例、压轴与创新题位置
- **风格标签**：识记型 / 情境判断型 / 归因分析型 / 计算推导型 / 案例综合型的占比

画像一旦定稿，组卷不得越表出题。

### Step 4　高拟合组卷

1. 按模块分配题量，确保每个画像考点至少被覆盖一次，高频考点按权重加权。
2. 按 `references/question-design.md` 逐题型命题：客观题做干扰项工程，主观题做采分点工程。
3. 过**质检门禁**（六项，见下），不合格的题当场重写，不带病入卷。
4. 用脚本渲染成卷，避免手工编号错位。

### Step 5　全真作答

给出卷面头（科目、级别、时长、满分、档位线、生成依据、作答说明）、倒计时建议、标记疑问题机制、交卷规则。作答可在线进行，也可导出打印卷。提交后不要追问"要不要看答案"，直接进入 Step 6。

### Step 6　判分与提分

用脚本判客观题、给主观题机器初评（采分点命中），明确标注"主观题初评，需人工复核"。输出：

- 总分 + 档位（对照该考试的档位线，不套用百分制）
- 分模块得分率、分维度得分率（如 CAK 六维）
- 错题清单：题号 / 考点 / 错因类型 / 正确思路
- **高价值失分点**：失分 × 该考点权重，排序而非只按错题数量
- 专项强化卷（只抽薄弱考点，题量 1/3）
- 到考试日的日程（按剩余天数分配：补知识 / 练主观题 / 全真二模）

## 竞赛模式（与考试模式的差别）

目标从"考试"换成"限时竞赛"（蓝桥杯、ICPC/CCPC、Codeforces、天梯赛等）时，流程不变，但产出物与判分口径必须改写：

| 项 | 考试模式 | 竞赛模式 |
|---|---|---|
| 答案 | 标准答案 + 采分点 | **没有标准答案**，只有题解与正确性论证 |
| 判分 | 对错 / 采分点命中 | **按测试点**：全部通过才算 AC；部分测试点可给部分分 `[按赛制确认]` |
| 计量 | 分数与档位 | 题数 + 罚时（ICPC 每次错提交 +20 分钟） |
| 输出 | 试卷 + 答案与解析 + 成绩报告 | 题面（描述/输入/输出/样例/约束）+ 测试点设计 + 题解 + 赛后复盘 |
| 质检 | 答案唯一、选项同构 | **约束自洽**：题面条件能让所有合法输入都有解；样例能验；时限与数据量匹配 |

竞赛模式必须额外交付两件东西：

1. **测试点设计**：每题至少 5 组——样例、最小边界、最大规模、随机对拍、卡常/特殊构造，并标明预期用途。
2. **赛后复盘**：开题顺序是否合理、卡题止损时间、可回收罚时（首题 AC 前的无效提交）、下一场要补的知识点。

蓝桥杯还要额外遵守：结果填空题只交最终结果（整数或字符串），不要求过程；编程题必须写清"从标准输入读入、向标准输出输出"，且题面不得只覆盖样例场景。

## 质检门禁（六项）

| # | 检查项 | 不通过的表现 |
|---|---|---|
| 1 | 考点合规 | 超纲、或与画像权重明显不符 |
| 2 | 答案唯一 | 客观题存在两个可成立选项；主观题无采分点 |
| 3 | 选项同构 | 干扰项一望即错、长度/结构突兀、暴露答案 |
| 4 | 难度校准 | 整卷难度系数偏离目标 > 0.1 |
| 5 | 情境真实 | 案例是教材例句改写、无真实冲突、无信息量 |
| 6 | 表述一致 | 英语卷混入中文解析口吻、术语不统一、指令含糊 |

## 脚本

两个脚本，路径相对本 Skill 目录。Windows 下路径含空格必须加引号。

```bash
# 组卷：spec → 试卷 + 答案与解析 + 质检报告
python scripts/build_exam.py --spec exam_spec.json --out out/

# 判分：spec + 作答 → 成绩报告（含薄弱点与专项卷建议）
python scripts/score_exam.py --spec exam_spec.json --responses responses.json --out out/
```

`exam_spec.json` 结构见 `assets/exam-spec-schema.json`；`build_exam.py` 会校验分值合计、答案合法性、维度覆盖，并把问题写进 `out/qc_report.md`。

作答文件格式（客观题填选项字母，主观题填原文）：

```json
{"A1": "B", "A2": "C", "C1": "I would join the celebration ...", "C2": "..."}
```

## 输出规范

- 文件命名：`<考试简称>-<级别>-模拟卷<序号>.md`、`-答案与解析.md`、`-成绩报告.md`。同一批次放同一目录，不散落。
- 卷首固定块：考试名称 / 级别 / 时长 / 满分 / 档位线 / 生成依据（官方资料份数 + 民间情报条数）/ 预测性内容占比。
- 每题标签：`[模块 | 维度 | 考点 | 难度 | 来源]`，写在解析里，不写进卷面以免泄题。
- 文档类交付优先用 Word/飞书文档；纯练习卷可用 Markdown 或 HTML 计时页。

## 边界

- 不复刻、不传播受版权保护的真题原文；只复刻**结构与规律**，题目全部原创。
- 不承诺命中率。博主观点一律标注为"预测"，并保留反押题提示。
- 主观题机器评分只作初评；口径差异大的考试（如申论、作文）必须给采分点让用户自评。
- 涉及具体考试的报名、费用、考点等信息，以官网当期通知为准；引用时附来源与日期。

## 快速开始

用户说"帮我准备 XX 考试"时，按 Step 0 → 6 直跑；用户只要一套卷时，跑 Step 0 → 1 → 3 → 4 → 5；用户只要诊断时，跑 Step 5 → 6（用已有作答或让其现场作答）。
